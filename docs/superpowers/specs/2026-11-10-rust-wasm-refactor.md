# phone-use 浏览器端 Rust/WASM 重构设计草案

日期为 2026-11-10。工作分支为 `codex/rust-wasm-refactor`，基线提交为 `e1e3bb46b85ffff1d859dc4e7ce6c014036df41f`。

## 已确认的目标和边界

用户要求新建分支并将项目重构为 Rust。现有服务端和 iPhone 原生控制引擎已经使用 Rust，本次工作集中在 `browser-control` 的浏览器客户端。

推荐迁移项目自有页面、会话状态、HTTP 请求、轮询、任务操作、坐标换算、Android 命令适配和视频帧管理，使用 Rust/WASM 编写。复用现有第三方 iPhone WebUSB、Tango ADB 和 scrcpy SDK，并通过职责有限的 JS 桥调用它们。此方案交付后，浏览器资产包含 WASM、桥接 JS 和第三方 SDK。

另一个方案是同时重写第三方协议能力，将 iPhone usbmux、配对记录存储、ADB 认证与流复用、scrcpy 3.3.3 控制和视频协议移植到 Rust/WASM。该方案的开发和设备兼容验证范围更大，需要单独核对上游能力及协议测试。

用户已确认方案 A，项目自有前端使用 Rust/WASM，第三方 SDK 通过 JS 桥复用。

## 组件和数据流

增加浏览器 Rust crate，使用 Leptos CSR 构建页面，使用 `wasm-bindgen`、`web-sys` 和异步 Rust 调用浏览器能力。复用现有 CSS、页面布局、控件和服务端 HTTP/WebSocket 契约。

Rust 浏览器代码负责以下功能。

- 连接、配对、就绪、错误、断开和资源释放状态。
- 会话创建、设备命令、配置与模型目录、初始化输入、任务创建、确认和停止。
- 独立的状态和截图轮询，以及迟到响应的会话归属校验。
- 页面坐标到截图坐标的换算，点击、长按和滑动识别。
- Android 命令到现有 ADB/scrcpy 能力的映射、元素树解析和坐标方向校验。
- WebCodecs 视频帧管理、截图转换、旋转检查和 PNG 回退。

JS 桥负责暴露第三方 SDK 的设备选择、认证、流对象、配对记录和 scrcpy 控制对象，以及必要的库兼容适配。USB 数据包组装、WebSocket 帧编解码等项目自有逻辑迁入 Rust。明确每个跨语言方法的输入、返回值、Promise、取消和释放契约。

用户点击连接后，在事件处理调用链中立即发起设备选择，再异步创建和准备会话。模型任务在 Rust 服务端执行，通过现有设备通道取得观察并下发动作。

## 行为和兼容要求

- macOS 桌面 Chrome 为首要浏览器验证目标，页面使用 HTTPS 或 localhost。
- iPhone 与 Android 保留当前连接入口、手动控制、任务模型选择和初始化流程。
- 保留浏览器配对记录与 Android 调试密钥的既有存储兼容性。
- 控制令牌和会话令牌仅用于相应请求，界面快照与错误信息清除凭据。
- 断开、USB 拔出、关闭页面和中继断开触发取消与资源释放。
- 配对期间的迟到 SDK 返回值仍被清理，USB 释放完成后允许重连。
- 会话切换后的旧截图和旧状态响应被丢弃。
- 设备动作仅派发一次，超时或取消后提示用户查看设备状态。
- 停止任务拥有独立请求路径，可以在其他页面动作等待期间发出。
- Android 视频继续使用浏览器 WebCodecs，并保留现有方向校验、中文粘贴与截图回退行为。
- 支持现有构建基础路径 `/iphone/`，Docker 构建生成 WASM、JS、CSS 和许可证产物。
